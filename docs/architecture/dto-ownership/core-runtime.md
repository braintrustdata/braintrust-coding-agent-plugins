# Core/runtime DTO inventory and ownership review

Reviewed against `1b4a4e611f1a9bc73c796361c9d82cdbf52bb721` before this refactor. Paths, line numbers, and existing-method columns describe that baseline. See [the review summary](README.md) for changes made from these findings.


Scope: production Rust outside agent/setup/managed-run/translator/import/Muse modules and all production TypeScript. Test fixture types and Rust associated-type bindings are excluded. Runtime actors/handles are listed explicitly as exclusions so coverage is auditable. Each row provides observed consumers and existing impl locations; a data-only judgment is deliberate, not an omission.

## Recommended implementation order

1. Split wire envelope responsibilities into one primary public type per module, preserving wire::* reexports. Move journal replay reconstruction to RedactedEnvelope::into_envelope and migrate callers; remove the old journal helper after verifying its module is private and only source_journal_path is reexported. Delegate SessionConfig project_name query to TraceDestination.
2. Put SessionRoute metadata/tag mutation behind type methods; keep parsing path resolution and plugin validation I/O outside DTOs.
3. Move AuthDiagnostic ready/unconfirmed constructors and status predicate out of trace_runtime; that type currently exposes combinations the call sites manually coordinate.
4. Consider command_output per-command modules and RPC per-method modules. Most leaf request/result structs should stay data-only; no constructor/getter additions without invariants.
5. Preserve TS structural interfaces. Shared route queries/normalization belong to a focused functions module, not JS classes just to emulate Rust impl. Typed TraceDestination is a separate contract improvement; current unknown destination field causes repeated assertions in Pi/OpenCode.

Important non-deduplication: sink::destination_components supplies project fallback while correlation::span_components preserves absence. They look similar but are not interchangeable. Preserve replay credentials/config semantics and the exported source-journal path API.

## Implemented in this stacked refactor

- `wire/envelope.rs` is now the single Envelope owner. AuthSelection, AuthSource, BackendAuth, CaptureContext, FlushMode, ProcessIdentity, RedactedEnvelope, SessionConfig, SessionRoute, TraceDestination each have a primary type file under `wire/`, with unchanged `wire::*` public exports. Existing wire behavior tests moved intact to `wire/envelope_tests.rs`.
- `RedactedEnvelope::into_envelope` owns replay conversion, including credential-free reconstructed config. All five internal replay/maintenance/ingress callers use the method. `journal::envelope_from_redacted` was verified internal-only (`mod journal`, not reexported) and removed after migrating all callers, so no public API compatibility shim is needed. A focused test asserts complete journal projection roundtrip and absence of replay credentials/config when route absent.
- `SessionConfig::project_name` delegates to the destination's existing query.
- `SessionRoute::apply_additional_metadata` and `apply_tags` own validation and mutation shared by setup, managed runs, import, and hook capture. Their existing regression tests now call methods; filesystem/plugin validation stays outside the DTO.
- `AuthDiagnostic` moved into `command_output/auth_diagnostic.rs`. It owns ready/unconfirmed construction, diagnostic-specific auth provenance labels, and ready/error status predicates reused by runtime warnings and daemon diagnostics. Serialized strings and the distinction between requested versus daemon-confirmed profile/org remain unchanged.

## Deliberately retained/deferred

- RPC leaf request/result schemas, command args, snapshot rows, options, and TS interfaces stay data-only unless already owning meaningful codec/conversion behavior. No mandatory one-type-per-file churn for local encoding helpers or tightly coupled tiny enums.
- JS types remain structural; no class conversion or TS protocol change in this PR.
- Different sink/correlation project fallback policies remain separate; their SDK output ownership deserves a dedicated contract review before consolidation.
- Plugin diagnostic matching/count aggregation and deeper RPC/per-command module splits remain optional small follow-ups; current private single-service implementations do not justify increasing this PR's surface.
